What it does

The Angular canvas draws an extra layer of outlines on top of the diagram: an orange box around nodes with a validation issue, a blue box around the node under the mouse, a blue dashed box around the selected node, and green boxes on valid targets while you draw a connection. Until now there was no setting for it, so an app that did not want them had to hide them with forced CSS. The pull request adds a [highlighterConfig] input: false turns the whole layer off, an object turns kinds on or off one by one.

The same canvas, before and after

Both shots are the same app built with the pull request, in the same state: Load clicked to select it, the mouse resting on Transform. The only difference is the input. Drag the slider to compare in place.

Before After

Counts are the overlay elements on the page in each shot. What stays matters as much as what goes: Load still shows that it is selected, with its own dashed border, resize handles and toolbar. Only the extra outline layer is gone, so users can still see what they selected.

What it replaces in an app

Before: forced CSS in the host component 
/* No canvas input for HighlighterController */
:host ::ng-deep {
  .grafloria-highlighter-validation,
  .grafloria-highlighter-hover,
  .grafloria-highlighter-selection,
  .grafloria-highlighter-connect-target {
    display: none !important;
    pointer-events: none !important;
  }
}
After: one binding 
<grafloria-diagram-canvas
  [highlighterConfig]="false">
</grafloria-diagram-canvas>

<!-- or keep some kinds -->
<grafloria-diagram-canvas
  [highlighterConfig]="{ showHover: false }">
</grafloria-diagram-canvas>

The CSS version still drew the outlines and then hid them, and it depended on internal class names that could change. The input tells the canvas not to draw them at all.

Follow-up: the same setting in React and Vue

React and Vue never drew this outline layer, so a highlighterConfig prop there would have had nothing to switch. The layer now lives in the shared renderer that every host mounts through, and React and Vue have the same prop with the same meaning. It is off unless you set it, so no existing React or Vue app changes when it upgrades. Angular is unchanged and stays on by default, as before.

Shots from a React app in a real browser: Ingest selected, the mouse on Transform. The colours are Angular's own. The orange outlines are the engine's warning that these nodes use a type nobody registered. Angular shows them too, so they stay; { showValidation: false } hides them and keeps the rest.

React · @grafloria/react 0.10.5 
<GrafloriaFlow
  nodes={nodes} edges={edges}
  highlighterConfig={{ showValidation: false }}
/>
Vue · @grafloria/vue 0.10.5 
<GrafloriaFlow
  :nodes="nodes" :edges="edges"
  :highlighter-config="{ showValidation: false }"
/>

Changing the prop takes effect immediately, without remounting the diagram. Plain JavaScript gets the same option on createDiagram(), plus setHighlighterConfig() to change it later.

Notes

  • An object is applied on top of the defaults, not on top of the previous value. So { showHover: false } means "everything on except hover". That is a sensible rule, and the comment on the input says so.
  • The test covers false. Validation, connect-target and the object form are not tested separately; they go through the same call, so this is minor.
  • Merged. The Angular README now lists [highlighterConfig], and it shipped in @grafloria/angular 0.13.6.
  • React and Vue got the same setting in the follow-up above: @grafloria/renderer 0.4.16, @grafloria/react 0.10.5 and @grafloria/vue 0.10.5.
